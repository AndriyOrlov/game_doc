## Чи можна додати оперативну пам'ять до VRAM

Фізичних 16 ГБ на дискретній карті не стає 48 ГБ від наявності 32 ГБ системної RAM. Є перенесення неактивних моделей/шарів у CPU-пам'ять і зворотне завантаження на GPU. Це спосіб знизити пікову потребу, з додатковими переміщеннями даних. Резерв RAM потрібен також Windows, Python і підготовці mesh.

[NVIDIA System Memory Fallback](https://nvidia.custhelp.com/app/answers/detail/a_id/5490) документує використання shared memory за браку GPU-пам'яті й нижчу швидкість. Driver Default дозволяє повернути стандартну політику; Prefer No Sysmem Fallback вимикає цей шлях. Не радимо перемикати весь ПК без вимірювання конкретного процесу.

Наш висновок: спершу керований low-VRAM/offload у вибраному pipeline, одна деталь за раз і роздільні shape/texture стадії. Shared memory не є гарантією, що будь-яка 24–29-ГБ модель запуститься з будь-якими CUDA-розширеннями.

## Вимірюваний тест, коли дійдемо до 3D

Голова або великий простий корпус без дрібного волосся/пальців. Спочатку базова геометрія, помірна роздільність, текстурування окремо. Зафіксувати модель і commit, ОС, GPU, версії PyTorch/CUDA і розширень, вільну пам'ять до старту, peak VRAM, peak RAM, час і якість mesh. Для RTX 50 перевірити сумісність усіх CUDA-розширень із конкретним середовищем, не копіювати старі інсталяційні команди без перевірки.

Тільки після одного успішного відтворюваного тесту обираємо основний інструмент. За бюджету 0 немає покупки хмарних кредитів. За поточним виробничим порядком зараз готуємо референси; фінальна генерація mesh після блокаута й механік.
